# Cloudflare npm ci fix

The deployment failure is caused by an out-of-sync `package-lock.json`.

`package.json` now declares `mux.js@7.1.0`, but the committed lock file in the repository was generated before that dependency was added. Cloudflare runs `npm ci` when it sees the lock file, and `npm ci` refuses to modify it.

Run this once in the repository and commit the regenerated lock file:

```bash
rm -rf node_modules package-lock.json
npm install
npm run typecheck
git add package.json package-lock.json
git commit -m "chore: sync npm lockfile"
git push
```

The updated project archive intentionally does not include a fabricated lock file because a valid npm lock must be generated by npm with the complete dependency graph and integrity metadata.

You may also temporarily delete the stale `package-lock.json` from the repository before the next Cloudflare build, but committing a freshly generated lock file is the recommended permanent fix.
